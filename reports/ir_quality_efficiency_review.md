# 应急响应质量与效率改进：本地验证记录

日期：2026-09-08。范围：SLEUTH 安装包、仓库评测与合成报告夹具；本记录是后续简化、提交与部署前的实验快照。实验没有访问真实 SIREN 主机，没有执行修复、部署、重启、提交或推送；下文统计仅对应当时输入。

工程检查通过，真实模型演练仍暴露结论校准问题。不能把这轮改动描述为已证明准确率提高或调用成本下降。

## 已落地的改动

- 易失证据优先、多主机先取最小快照；保留九类基线和六维覆盖，复用已有证据，昂贵扫描按问题逐级扩大。
- findings 从调查开始持续维护；证据保留身份、原文、时间与完整性；同名主机以 Client 区分，已有底稿不覆盖。
- 修正 mtime/ctime、告警延迟、WAF 来源、SSH 会话、OOB 资产范围、云助手祖先与外传量的判断边界。
- 核验直接针对准备交付的草稿。发送时保留已裁决措辞，不能在摘要里重新升级断言或扩大建议范围。
- 增加隔离模型运行器、同名资产与伪指令组合场景、离线 bookkeeping/超时/权限测试；修复 mock 对结构化客户端缺少命令文本的问题。
- 报告结构检查接入 CI；新增[事实复核流程](../evals/output/review.md)，标注历史盲评入口已失效，保留原 pending 状态。

## 验证范围

`validate.py`、`permission_probe.py`、967 项离线自测、四份报告合同检查、`gen_trust_report.py --check` 与 `git diff --check` 均通过。

通用 doc-ref checker 只扫描根 AGENTS/CLAUDE 与其支持的布局，不覆盖本项目全部 Skill references。安装包由 `validate.py` 实际检查 40 个 Markdown 文件；修改文档的本地 Markdown 链接另行检查，运行时治理中提到的脚本路径也已直接核对。

信任报告把模型运行器列为显式联网例外：使用用户配置的 Claude Code 模型服务，仅在仓库外新目录写产物，未纳入 CI 或安装包。源码摘要变化会使该例外失效，必须重新审阅。运行器拒绝用户已有的 Read/Write/Edit、工具通配授权与 additionalDirectories，避免授权累加泄露场景答案；这是 CLI 工具隔离，不是操作系统沙箱。本轮配置未发现这类扩权。

## 报告事实复核

四份完整报告均通过隔离 writer 重新生成；后三份 writer 的本地 Write 匹配未放行，编排者从其已生成的目标文件内容接收稿件，再在本地落盘及复核，没有访问远端或给 writer 增加工具。

复核捕获并修正了合同校验以外的问题：复杂 RCE 报告把下载源与控制端混为一谈、补写未核验的 WAF 配置；多主机报告把令牌读取主体写成 automation-runner，并把单令牌吊销说成整个账号失去执行能力。还修正了处置措辞、动作数量和样本文字重用。最终保留证据允许的主机事实、既有不确定性与处置状态。

四份夹具是合成事实回归，不是生产应急报告，不证明一次调查的准确率。历史 findings 缺少新证据编号、Client 映射或截图时保留缺口，不补造字段；图片仍是模板要求的占位。

## 最终交付门复测

两轮均正常结束并生成 findings，但全稿质量仍为 fail：

- `delivery-gate-03`：建议已从目录级收窄为 MD5，扫描解释也保留为候选；但首句仍将未核验的告警整体确认为误报，并将 atime、文件属主推成过强的完整性证明，遗漏场景中可用的 journal 记录。
- `delivery-gate-07`：不再用 HTTP 200/字节数直接证明命令执行；但仍把 mtime/ctime 差异解释为“只能由 touch 回改”，把时间相关性升级成精确上传/回改动作，对来源地址的代理边界也未完全落实。

因此本轮交付的是已验证的工程改动、真实缺陷记录和后续复测入口；结论校准问题尚未稳定解决。不得把 14 轮执行完成、967 项自测通过或 4/4 模板检查当成整体模型质量通过。下一次正式效果评估应冻结模型/Skill/场景/运行器，补齐每场景三轮匹配对照，并优先检验交付措辞与独立核验的实际执行情况。
