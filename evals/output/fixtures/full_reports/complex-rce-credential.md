排查从云安全中心 2026-07-22 02:15 对 api01 产生的异常进程告警开始。告警显示业务进程 `java` 派生了 shell 子进程，这在对外 API 服务的正常运行中不应出现，因此我们以只读远程取证方式检查了主机的进程启动记录、文件访问记录、crontab、审计记录和进程网络记录，并核对了同一时段的访问日志。

入口可以确定为 `/api/export` 接口的命令注入。访问日志原始行 `203.0.113[.]77 - - [22/Jul/2026:02:14:08 +0800] "POST /api/export HTTP/1.1" 500` 显示，该来源提交的请求体含有 shell 元字符，接口返回 500；两秒后的进程启动记录显示 `java` 于 02:14:10 派生 `sh`，执行下载命令并运行 `/tmp/.cache-upd`。请求时间、进程父子关系和请求内容能够对应，这说明注入的命令确实在业务进程下被执行。该接口为客户自研代码，没有对应的公开漏洞编号，修复需要由业务方在代码层完成。

下载落地的文件 `/tmp/.cache-upd` 修改时间为 02:14:10，sha256 为 demo-bbbb2222，与进程启动记录中的下载动作在时间上一致。进程网络记录显示该文件运行后曾连接攻击源地址 203.0.113[.]77，说明该程序运行后回连了攻击源。

这是一起由公网 API 命令注入引发的主机失陷事件，攻击者在业务进程下执行命令、读取了配置文件中的云凭据并建立了计划任务，主机侧证据链完整；目前公网入口已隔离，计划任务已删除，主机重建和云凭据轮转仍在进行。事件暴露出两处控制缺口：对外接口对用户输入缺少校验，云凭据以明文保存在业务主机的配置文件中。客户下一项最高优先级工作是完成旧凭据吊销并补齐对应账号的操作审计记录，在此之前不应认为凭据泄露的影响已经关闭。

### 阿里云安全产品与服务建议 / Alibaba Cloud Security Recommendations

以下建议基于本次事件暴露的安全控制缺口，按处置优先级排列。实际开通范围应结合现有订阅、资产规模和技术评估确认。

::: recommendation priority=P1 type=product
name :: Web 应用防火墙（WAF）
risk :: 对外 API 接口直接暴露在公网，含 shell 元字符的注入请求可以直接到达业务进程。
reason :: WAF 可以在请求到达业务进程前拦截命令注入特征，并保留完整的请求记录，在代码修复完成前提供一层阻断。
action :: 将 api01 及同类对外接口接入 WAF，开启命令注入防护规则，并在漏洞修复验证前保持拦截模式。
:::

::: recommendation priority=P2 type=product
name :: 操作审计（ActionTrail）
risk :: 凭据泄露后缺少可追溯的账号调用记录，泄露影响的范围难以收口。
reason :: 操作审计可以长期保存账号的 API 调用记录，为凭据泄露事件提供可追溯的使用范围。
action :: 开启全账号操作审计并投递到长期存储，同时配置对业务凭据异常调用来源的告警。
:::
