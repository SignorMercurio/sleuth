> 排查对象为 gateway01 和 worker02 两台主机，采用只读远程取证，并结合云安全中心告警（ID 920001、920002）、WAF 与访问日志及操作审计。两台主机的网络外联、进程启动、登录记录和云安全中心告警均从 2026/07/20 起可查，操作审计从 2026/07/01 起可查。

#### gateway01：模板注入与令牌读取

WAF 在 01:05:12 命中模板注入规则，请求来自 203.0.113[.]88，访问日志在同一时刻记录到对应的 POST 请求。两秒后，进程启动记录显示网关进程派生 shell（`gateway -> sh`），文件访问记录显示该 sh 进程读取了 `/etc/automation/token`。三类记录在时间上前后衔接，说明攻击者经模板注入执行了命令，并拿到了自动化令牌。

WAF 只保留命中规则的请求，攻击者在 01:05 之前是否做过探测无法确认。2026/07/20 以来，gateway01 未观察到其他异常外联或异常登录，也未发现恶意文件、计划任务或启动项，系统关键文件未见篡改。

#### worker02：经云助手下载并运行脚本

操作审计显示，automation-runner 在 01:09:33 以 worker02 为目标下发命令。三秒后，进程启动记录显示云助手进程启动 shell 下载 `/tmp/diag.sh`；从 01:10:02 起，该脚本执行系统与网络信息收集命令。进程启动记录完整覆盖了从云助手到 shell 的进程链。

2026/07/20 以来 worker02 未观察到交互式登录。攻击者在这台主机上的操作都经由自动化工具完成，没有证据表明其取得了登录权限。主机上未观察到计划任务或启动项。

#### 跨主机关联分析

两台主机由 automation-runner 串联起来。gateway01 上的令牌在 01:05:14 被读取，约四分钟后操作审计记录到同一账号向 worker02 下发命令，worker02 三秒后开始下载脚本，操作审计也把这次下发与攻击源 203.0.113[.]88 关联在一起。账号、时间和命令内容前后衔接，可以确认 worker02 失陷源于 gateway01 泄露的令牌，worker02 本身没有被利用的漏洞。

## 总结与安全建议 / Summary & Advisory

### 事件总结 / Event Summary

<!-- 先用两三句收束事件：根因、结果和关键控制的得失，不重复影响明细和攻击过程；再用一个短段写尚未解决的问题及下一步最高优先级工作。必要的长期加固建议写清对象与动作；下一步排查动作（如补查某类日志）写在这里，后文产品或服务建议只写产品的开通和配置，两边不重复。若已无待办，依据验证结果简短说明，无需补建议凑篇幅。 -->

这起事件的根因有两点：gateway01 存在服务端模板注入漏洞，而能向其他主机下发命令的自动化令牌又以未加密文件存放在这台对外主机上。攻击者因此在几分钟内从公网入口扩展到内部节点 worker02。云安全中心在攻击发生后一两分钟内即产生告警，但止损动作近七小时后才开始。

目前最优先的是完成网关漏洞修复并确认上线，以及完成 worker02 重建，两项都完成后再恢复接口和自动化任务。自动化任务重新启用时，应把令牌可操作的主机限定在实际需要的范围内。
