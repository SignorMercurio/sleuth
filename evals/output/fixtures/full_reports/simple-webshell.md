排查从云安全中心（SAS）的「Webshell 通信」告警（ID 900001）开始。告警发生在 2026/04/17 18:20:05，对象是 web01。排查通过只读远程取证进行，调取了 SLS 采集的 Web 访问日志和 SAS 的进程启动记录，并检查了主机上的文件、启动项、账户和系统文件完整性。

> 访问日志从 2026/04/10 起可查，更早的记录已轮转；进程启动记录和云安全中心告警从 2026/04/12 起可查，此前的主机活动无法据此排除。

访问日志显示，攻击者先对上传接口做了探测。2026/04/17 18:12:03 至 18:17:41，来源 203.0.113[.]45 向 `/upload/` 接口连续提交了 9 次 POST 请求，每次变换文件名后缀，均返回 400。18:18:12，同一来源对 `/upload/x.php` 的首个 POST 请求返回 200：

```
203.0.113[.]45 - - [17/Apr/2026:18:18:12 +0800] "POST /upload/x.php HTTP/1.1" 200
```

服务器上 `/var/www/upload/x.php` 的修改时间为 2026/04/17 18:18:12，与这条请求一致。据此判断，攻击者利用自研上传接口的文件过滤缺陷，把 PHP Webshell 写入了网站上传目录。该漏洞属于任意文件上传，没有对应的 CVE 编号，需要由业务方修改接口代码修复。

![](simple-webshell.assets/TODO-access-log-upload.png){caption="图 1 | 写入 x.php 的访问日志（SLS · web01）"}

文件写入约一分半钟后，SAS 进程启动记录在 18:19:40 捕获到 Web 服务进程 php-fpm 启动 shell 执行命令，进程链为 `php-fpm -> sh -c "id"` 和 `php-fpm -> sh -c "whoami"`。这两个 shell 是 Web 服务进程下的异常子进程，出现时间紧随 Webshell 写入，25 秒后云安全中心即发出 Webshell 通信告警。由于没有取得完整的命令回显，攻击者与 Webshell 的交互过程无法完整还原；综合落地文件、进程链和告警时间，判断攻击者很可能已经通过 Webshell 执行了系统命令。

![](simple-webshell.assets/TODO-sas-process-chain.png){caption="图 2 | php-fpm 启动 sh 的进程链（云安全中心 · web01）"}

命令执行之后，在进程启动记录覆盖期内未观察到可疑的外联连接，也未观察到稳定的远程控制通道。主机上未观察到攻击者留下的定时任务、systemd 服务或 rc.local 启动项，未发现新增或异常账户；`rpm -Va` 校验未发现关键系统文件被篡改。

### 事件总结 / Event Summary

<!-- 先用两三句收束事件：根因、结果和关键控制的得失，不重复影响明细和攻击过程；再用一个短段写尚未解决的问题及下一步最高优先级工作。必要的长期加固建议写清对象与动作；后文产品或服务建议已覆盖的内容不重复。若已无待办，依据验证结果简短说明，无需补建议凑篇幅。 -->

事件的根因是自研上传接口的文件过滤存在缺陷，攻击者探测几分钟后就写入了 Webshell，并很可能借此执行了系统命令。云安全中心在命令执行后很快发出告警，但到目前为止 Webshell 仍未清除，上传漏洞也仍然存在。

最优先的工作是完成止损：删除 Webshell，停用或修复上传接口，并封禁攻击地址。止损后需要补上两处无法确认的边界，一是检查 web01 主机上的登录日志，判断攻击者是否登录过服务器或数据库；二是采集相邻主机的进程和网络数据，判断攻击者是否横向移动。
