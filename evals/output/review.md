# 输出事实复核

`validate_full_reports.py` 验证模板结构、关键词、严重等级与篇幅上限等合同，不判断自然语言事实。
不设正文最低字数；阿里云安全产品与服务建议小节必须保留，包含 1 至 3 项与事件风险或证据缺口对应的建议；已有产品优先补齐配置。动作和时间线数量按案例证据设定，不能为过门补写事实。
即使校验通过，新增的外传结论、主机错配或处置状态升级仍可能漏检。

```sh
python3 evals/output/validate_full_reports.py \
  --output-json /tmp/sleuth-full-report-eval.json \
  --output-md /tmp/sleuth-full-report-eval.md
```

报告规则变化后，用隔离 writer 只读取对应 findings、模板、样例与写作参考重新生成受影响夹具。
随后由另一位复核者逐条对照 findings；复核者可为模型，但应明确记录身份，不能称为人工盲评。

| 核验项 | 裁决依据 |
|---|---|
| 新增事实 | 每条承重断言都能回指 findings 的证据原文；模型补写的合理故事也算错误 |
| 置信度 | findings 的推测不能升级为确认；直接观察不能自动升级为身份、因果或影响结论 |
| 资产与时间 | 主机、Client、账号、事件时间与采集时间不可互换；缺失字段不得补造 |
| 处置状态 | 建议、进行中、已完成分别核对；勾选状态和正文必须一致 |
| 覆盖与首句 | 日志缺失不能写成无异常；标题、摘要与处置建议保留相同边界 |

记录 `夹具或演练标识 | 断言原文/行号 | findings 依据/行号 | 保留/降级/删除 | 理由 | 复核者`。
没有证据支撑的重要结论即不通过，不能靠文风、更多技术编号或较短耗时抵消。

## 必须能拒绝的反例

以下是故意错误的候选句，不是场景事实。复核者在看过输入后应能指出具体反证或缺口：

| 输入 | 候选句 | 应拒绝的原因 |
|---|---|---|
| `fixtures/web01-webshell.findings.md` | 攻击者已窃取全部客户资料。 | 没有内容或体量证据，凭据出现不等于成功外传 |
| 同上 | WebShell、持久化和受影响凭据均已清除。 | 底稿的处置尚未开始，不能把建议变成已完成 |
| `fixtures/app01-no-current-intrusion.findings.md` | 已排除六月三日发生入侵。 | 现存证据从七月十三日开始，不能排除历史事件 |
| `fixtures/api01-rce-credential.findings.md` | 203.0.113.45 入侵了 api01。 | 把另一夹具的来源地址混入本事件 |

## 对照与盲评

真实调查产物与成本采集见 [运行时评测](../runtime/README.md)。对照双方必须使用固定场景、
实际模型、相同可用工具与停止条件，并保留每轮原始产物与输入哈希。先判事实正确性和覆盖，
再比较耗时、调用与输出字节；失败或未完成的轮次单列。

需要人工盲评时，由协调者随机将两份输出标为 A/B、隐藏 Skill 标签与答案映射，向评审提供
同一份事实材料。评审记录 `A 更好 / B 更好 / 持平 / 均不合格`、具体事实依据、姓名和时间，
提交后再揭示映射。未实际完成的人工判断保持 pending，不得由模型代签。

`reports/output_review_adjudication.md` 和旧 scorecard 是历史静态评测快照。其中引用的
`scripts/yao.py`、`scripts/adjudicate_output_review.py` 已不在本仓库，不能用来重新执行评审；
也不能把历史静态得分当作当前模型效果。当前复核使用本页流程和实际存在的校验入口。
