# 步骤 7：对抗式验证与结论交付

SKILL.md 步骤 7 加载本文件，裁决口径以 SKILL.md「核验裁决」为准，报告交接以步骤 8 为准，本文写细则。先按「核验流程」过验证门，再按「定稿与交付」交付。目的：每条「承重断言」先经独立核验再定稿，系统化防止误归因。各调查指南与 `tech_*` 技巧里的判读注意事项在此集中成一道强制门。

## 承重断言（逐条过门）

会写进结论或正式报告、且支撑定性或处置的断言：事件定性（什么攻击 + 是否得手）；入侵路径每一步（入口 / 执行 / 外联 / 持久化 / 处置）；每个标出的 ATT&CK 技术；每条「攻击者做了 X」；每个 IoC 的归因；时间线关键节点（T0、止损点）；影响处置的阴性判断（据此停止排查、判定无需隔离、宣称风险已清）。过程描述不必过门；「未观察到」措辞不免检。

## 核验流程

1. 先把准备交付的事件定性与建议动作范围写进 findings（§2、§9），再从 findings 列出全部承重断言；定性和动作范围必须在列。
2. 逐条（多时按章节分组）交独立核验：运行时有子 agent 就派，只给「断言 + 所引证据 + 本清单」，不给主 agent 的推理；无子 agent 则主 agent 换「我要推翻这条」的视角自检。核验方默认存疑、尽力反驳，可跑少量定向只读命令补证（同受只读护栏约束），不重做整轮采集。
3. 裁决：被反驳或证据不足 → 降级（「已确认」→「推测」/「无法确认」）或删除；「未观察到」只用于实际检查范围内无命中，不替代未查或失败。扛住反驳 → 保留确定措辞。
4. 产出核验表 `断言 | 裁决 | 反驳依据 | 交付措辞调整`（内部用，不进交付内容），裁决与措辞写回 findings，再按「定稿与交付」执行。

## 反驳清单

按断言类型逐条质疑。每条写的是「要有什么证据」与「没有就怎么写」。

**时间**
- `atime` ≠ 攻击者访问：扫描、备份、杀软读取都会刷新；要有 Web 日志或进程记录交叉。
- `ctime` ≠ 落地时间，mtime 早于 ctime 只是回改候选（判读见 `references/tech_process_file.md`）；不补写「用 touch 回改」等未观察到的具体动作。候选筛选须同时按 mtime 与 ctime，不能只验证已找到的文件。
- 事件时间、检测时间、入库时间分别记录（校准见 `references/tech_log_analysis.md`）；窗口无命中先查覆盖与字段语义再扩窗。

**存在 ≠ 利用 / 得手**
- 文件存在 ≠ 当前可用：查中间件配置（如 `location ~ \.php$ { return 403; }`）+ 实际访问状态码。
- 上传成功 ≠ 利用成功；SUID / 可疑二进制存在 ≠ 已用于提权，要有调用证据。
- 当前为空、无执行位、进程不在或日志无命中 ≠ 历史从未执行；HTTP 200 与响应字节数 ≠ 命令执行或数据外传。分别用历史执行记录与具体响应内容验证。

**来源归因**
- WAF / 应用来源先核代理链与字段信任（`references/tech_log_analysis.md`）；SSH 按准确会话归因（`references/sas_sls_host_telemetry.md`「SSH 登录来源归因」），不凭 PID 邻近或时间相邻归因。
- 对 WebShell 目录后来的 GET / 访问 ≠ 原始上传源，只能写「近期访问 / 探测」。
- 文件时间与某次登录或传输相近 ≠ 该会话是唯一写入者；要有该会话的操作记录，否则列为候选。
- IP 归属与信誉要外部情报佐证，不凭地域臆断。

**云端与阴性判断**
- WAF `waf_action='block'` ≠ 实际拦截：结合 `waf_test` / `final_action` / `upstream_status` / `status`；测试或观察模式不是真拦。
- 「未检出」≠「未发生」：核对日志覆盖窗是否早于攻击窗；遥测起始晚于攻击窗只能写「无法据此排除」。
- 阴性断言同时检查：资产 / 账号正确、采集完整、命令成功、过滤不过窄、无未读分页或截断；缺任一项就写明限制范围（如登录或日志样本量不足，不得据此排除暴破、登录或外联）。
- 标题、首句与处置建议和正文保持同一边界：正文承认覆盖不足，开头不能写「不是挖矿」「未失陷」「误报」。配置注释、进程名与本机发布清单也可能被改，关键可信性另行核验。
- 检测机制的解释（扫描触发、告警规则误报）只是候选，要有扫描记录或机制文档支持才能写成原因。
- OOB / DNSLog 域名命中 ≠ 主机失陷：需 shell 子进程、payload 下载、反向连接、落地文件、异常登录、持久化或新告警等跟进证据才能升级定性。

**因果与孤证**
- 父链 / 时间相邻先问是巧合还是因果；每个标出的 ATT&CK 技术要有具体证据，不因「这类攻击通常会」标出。
- 先拆开直接观察与因果推断：一条可靠来源的记录只能确认「该来源记录了 X」，不能同时确认攻击者身份、入口、执行成功与影响。
- 得手、入口、归因、跨主机关联需至少两类独立证据并排除合理替代解释；同一原始事件的告警、API、截图和转述算同源；客户确认只支持其实际确认的动作。
- 一类记录的时长不能推导另一类行为的时长（如 SSH 会话时长 ≠ C2 持续时间）。
- 核验范围不外推：单个文件的核验不能扩成目录级或供应商级加白。
- 缺失能力只限制依赖该证据的断言：已充分支持的局部事实可以确认，未覆盖范围保留缺口；不因多读一个来源自动升级整条攻击链。

## 定稿与交付

- 运行环境提供 `case_update` 时，未过验证门的 `confirmed` 事件改为 `inferred` 或 `withdrawn`，然后按 `references/findings_spec.md`「攻击时间线位置」把事件快照写入 §3 和 §5。
- 每台主机过完验证门后，把逐轮维护的 findings 标记为「已验证」，核对定稿断言与证据引用，未决问题保留在工作区段（结构见 `references/findings_spec.md`）。
- 多主机委托时继续下一台的定向调查，复用已采最小快照并补查可能已变化的状态；全部完成后统一交付。
- **跨主机关联断言**（同源攻击、横向移动、同一攻击者）基于多份 findings 提出，同样要过验证门；裁决连同所引的另一份底稿名写入相关各台 findings。
- **核实模式**：把既有报告或 findings 的承重断言当作待核断言过同一验证门（没有 findings 时以报告为等价物），交付「核验流程」第 4 步核验表的对外版（附证据编号），并指出话术与证据不符处。
- 交付形式是对话中的精炼调查结论，内容见 `references/findings_spec.md`「结论交付层使用规则」，按下节起草、复核并原样发送。

### 结论交付隔离

全部 findings 标记「已验证」后，运行时支持子 agent 时派生一个全新结论 writer 起草交付结论。只给它全部 findings 文件路径与 `references/findings_spec.md`，不传调查对话、工具输出、编排者推理或核验表。它按「结论交付层使用规则」返回草稿，不创建文件，不调用 SIREN、SAS、SLS、OpenCLI 或联网工具。

编排者逐句对照 findings 复核，只判通过或不通过，不改写草稿：每条断言都要对得上已验证章节的措辞等级、数量与范围，IoC、时间与路径逐字一致。不通过时，findings 本身有误或需要新增、加强断言的，先改 findings（新增或加强的断言回到「核验流程」过门）；草稿越界的，把问题清单交回 writer 重写。问题清单只写原句、违反的规则和对应 findings 章节，不附改写文本或新事实。重写稿重新复核。通过后把 writer 稿原样发送，不增删字句，不追加调查过程说明；末尾只可另起一行给出 findings 路径并询问是否生成报告。

运行时不支持子 agent 时，编排者重新读取全部 findings 后内联起草，只用文件内容，不凭会话记忆补事实或改措辞，再做同一复核。

交付前核对 findings §2 的严重等级、§9 的当前事件状态与处置进展已填写或已核实为未知，不把缺口留给 dossier 的写作层猜测。
