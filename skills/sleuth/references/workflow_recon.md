# 步骤 1–2：模式判别、初始化与初步信息收集

SKILL.md 进入步骤 1 时加载本文件。安全护栏、模式定义与报告确认门以 SKILL.md 为准，本文只写操作细则。

## 输入与模式判别

输入分为三组，据此**自动判断**调查模式：

- **UID**（阿里云账号 ID）+ 以下一个 **SAS 告警选择器** → **模式一·告警驱动**：
  - 告警列表返回的数字 **告警 `Id`**
  - **云安全中心资产 UUID**
  - **ECS 实例 ID**
- UID 与选择器均缺失 → **模式二·自由调查**：跳过告警详情，向用户问异常现象作线索，文件名用主机名 + 日期（无 event_id），无需追问
- 仅缺 UID 或选择器 → 先问用户，拿不到则进入模式二
- 同时给出多个选择器 → 让用户确认本次查询范围，不要把互斥参数组合后交给 `$sas`
- **Client ID**（SIREN 客户端）缺失 → 用 SIREN list client 工具列出客户端让用户选

两个正交的范围判定：

- **多主机委托**：用户点名多台主机 / 多个 Client，或告警显示多资产受影响 → 主机清单在步骤 1 确定，先按步骤 2 覆盖各主机最小快照，再逐台深挖并完成步骤 3–7；每次 SIREN 调用绑定对应 Client
- **合并模式**：用户直接提供多份既有 `IR-….md` 报告并明确要求合并 → 该请求即为报告确认；跳过调查（步骤 1–6），把报告当 findings 输入进入步骤 8；合并层新铸的断言（同源攻击、横向移动等）仍须过步骤 7 验证门

## 步骤 1.1 确认能力、Client ID 与范围

调用 SIREN list client 工具确认可达且目标在线，未指定 Client 则展示列表请用户选。本次已有有效列表时直接复用，状态变化才刷新；不为能力探测在受害主机上跑命令。**退出条件**：SIREN 工具缺失、不可达或无可用客户端 → 告知用户并结束，不改用本地 shell/SSH。

从运行环境清单确认 `$sas`、`sls`、`opencli-aliyun-ir`、子 agent 与联网检索是否可用；云侧 skill 不确定时仅在需要时试调一次，失败即记缺口。截图浏览器桥由 `opencli-aliyun-ir` 委派时自报，不单独探测。工具映射与降级见 `references/runtime_compat.md`。

多主机委托时在此确定完整主机清单与调查顺序（首发告警或影响最严重的主机优先）。调查过程中证据指向清单外的主机（如横向移动目标）时，向用户确认后追加到清单。

按 `references/findings_spec.md` 为每台主机初始化工作底稿并标记「调查中」，确认已有文件是本次续查还是另一轮调查；记录 Client 与云资产映射、调查起点，之后每轮补写，不等步骤 7 才落盘。

能力缺失项、判定依据和受影响的调查方向记入 findings 的「云端证据覆盖」与「证据缺口」，交付时说明相关限制。按 `references/verification_checklist.md` 逐条裁决断言，不因工具缺失统一降低全部结论，也不把未覆盖写成「未发生」或用替代来源抹去缺口。

## 步骤 1.2 【模式一】获取告警详情

只调用 `$sas` skill，传入 UID 与一个用户已确认的选择器；用户明确给出的 region 原样传递，其余默认值、分页与参数格式由 `$sas` 管理。

- **数字告警 `Id`**：直接让 `$sas` 查询详情；只使用用户提供或列表返回的 `Id`，不用 `AlarmUniqueInfo`。
- **资产 UUID / ECS 实例 ID**：先列告警；用户明确给出的时间窗只传给列表查询，不自行推断。按用户请求的范围继续分页，把 `$sas` 返回的全部告警摘要作为本次调查输入，不要求先选出唯一告警；需要支撑调查方向、事件定性或影响范围时，再用对应的列表内数字 `Id` 逐条查详情。空列表是有效结果，说明该范围未返回可见告警，再询问是否补充线索转入模式二。
- **统一落点**：资产 / 实例列表输入即使返回多条也只形成一组事件结论；如用户确认生成报告，只生成一份。文件名与 findings 交接分别按 `references/report_naming.md`、`references/findings_spec.md` 执行。

## 步骤 1.3 【模式二】获取用户描述

询问：观察到什么异常？何时开始？有无可疑文件/进程/IP 线索？

## 步骤 2 初步信息收集

1. **最小快照**：先核对系统类型、主机标识和时间；优先取告警目标进程的父链/启动时间、当前连接、关键文件元数据，再按需读内容。对已授权的每台主机先完成这一轮，避免首台深挖期间其他主机的进程或连接消失。读文件前先取元数据，并记录采集时间；只读采集本身也可能刷新 atime。
2. **轻量基线**：补齐系统信息、时间主机名、高 CPU 进程、当前连接、监听端口、登录历史、定时任务概览、相关临时目录变动、云助手子孙进程九类。按 Linux/Windows/容器及可用权限选等价只读检查，不适用或不可获取的项写明原因；临时目录时间窗依据事件线索，不固定近 24h。云助手祖先只触发 `references/tech_cloud.md` 的任务关联核验。
3. **定向问题**：列出最多 3 个会改变事件定性、影响范围或处置建议的**待证问题**，每个问题写明当前假设、最短必要证据、资产与时间范围。后续命令必须服务其中一个问题或步骤 6 的残留风险覆盖；不要为了“多取证”无目标扩张范围。

每轮只并行互不依赖且成本可控的检查；耗时扫描不要与易失证据采集挤在同一批。结果仍有效且范围相同时直接复用，重复采集必须说明状态变化或需要覆盖的新时段。

发现正在加密、持续外传等紧急迹象时，先对决定动作的最小断言执行步骤 7 的定向核验，及时告知已知事实、限制和建议；持续推进后续调查，不等全部主机定稿，也不越过只读处置边界。
