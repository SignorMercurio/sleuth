# 报告写作风格指南

步骤 8 写报告前读取本文件，成稿后再用它复核。目标：用自然、准确、克制的中文交代事件，方便客户判断影响和安排处置。下面的规则与 `assets/style/` 中的手写报告片段共同约束文风。

## 风格语料的使用

- 写作前只读 `assets/style/curated-ir-excerpts.md`（存在时）找语感；不存在才从目录中最多挑 1 篇其他材料，不为模仿文风加载额外长文。
- 样本只影响内容取舍、段落节奏和常用表达；事实、结论等级、篇幅、模板结构和本项目约束始终以 findings、模板及对应规则为准。样本里的案例、命令、IP、结论一律不得进入报告，句子也不得照抄或只换主语改写（校验器会拦截连续重合的样本原句）。
- 样本有增删后，本文件的蒸馏规则需要人工重新核对一次。

## 改写边界

先按 findings 和模板成稿，再处理能定位的问题。每处改动应能说清原句哪里空转、重复或难以理解；已经自然、准确的句子保留，不顺手换词，不为制造节奏调整句长或段长。拿不准时保留原句。

文风修改不改变事实、判断强度、时间关系、影响范围或处置状态，也不靠新增因果、动机、数字和场景让句子更具体。尤其保留「很可能」「在覆盖期内」「尚未确认」等影响结论的限定；来源要求见 `findings_spec.md`。模板标题、字段名、列表结构、指令块语法、原始引文和代码不是润色对象，块内的叙述仍按本指南复核；章节取舍按 `report_writing_rules.md`。

报告采用专业书面语，不强加「我 / 你」、口语词或情绪。长句、被动句、名词化、并列结构和重复资产名称本身不构成问题；操作步骤与证据清单可以保持整齐，资产名称重复有助于避免多主机串案。

## 句法与叙述

- **结论先行，推理透明**：先给承重判断，再跟最强依据。决定结论的判断要说明证据；同一依据支撑一组相邻事实时只解释一次，不逐句重复来源。
- **用完整段落叙述，列表用于枚举**：按证据之间实际存在的时间、因果或对照关系连接句子，不逐段套用「检查了 X，发现 Y，因此 Z」。并列的方法、线索与待办用列表呈现，每项是完整的动作或判断。
- **按语义组织句段**：一段围绕一个核心判断展开。需要缩短报告时减少低价值内容，不压缩句法；一个句子同时塞入结论、多条证据、影响和处置，导致关系难以辨认时再拆句，不按字数或顿号数量拆分。
- **平实、克制的书面语**：直接陈述观察和判断，删去「遗憾的是」「好在」「不难发现」等情绪或引导语，不用修辞放大风险。
- **不确定性如实标注，且双向校准**：把握程度直接用「可能 / 很可能 / 推测 / 疑 / 未必」写进句子，证据用语按模板注释区分「未观察到」「无法确认」「已排除」，不将它们互换，也不当固定收尾。按 findings 的裁决措辞，既不把「很可能」抬高为「已确认」，也不把已有判断一律弱化为「待进一步确认」。不写「大概率得手」等口语化判断，不用 `[推测]` 标签或另起置信度说明，把具体行为、判断强度和依据写在一起。
- **影响结论的数字与范围写具体**：已有记录能说明对象、数量或时间时，直接使用，不用「大量」「显著」「全面」盖掉它们；没有数值就保持定性表述。不影响定性、范围或处置优先级的精确数字不必写入正文。
- **证据贴身解释**：日志、命令输出紧跟它支持的判断；「这说明……」后应有证据支持的新判断，若只复述上一句就删去重复。跨段指代不清时点明资产、记录或行为，不用「值得注意的是」代替对象。
- **中英文之间留空格**，专有名词用原文（WAF、ECS、Webshell），标点用全角中文标点。面向管理层的概述 / 结论里阿里云产品用中文名（云安全中心、云防火墙），`SAS` / `SLS` / `ActionTrail` 等缩写留给技术分析里的日志源与标识符。客户可见叙述优先写「访问日志」「进程启动记录」，不写「Access 日志」「进程遥测」；只有原始字段名、产品界面名称或日志库名称必须精确引用时才保留原文。

## 成稿中的常见问题

以下是回读线索，不是禁词表。先确认句子存在对应问题，再做最小改动；不因出现某个词或标点直接改写。

| 问题 | 改法与保留边界 |
| --- | --- |
| 虚设误解再翻案，如「真正的问题不是 X，而是 Y」 | 没有需要排除的具体假设时直接写 Y 及依据。证据确实区分了两种解释时保留对照，不能删掉已排除的假设或调查边界。 |
| 「先说结论」「核心是：」「值得注意的是」等提示语没有增加信息 | 删掉提示语，直接写判断。冒号用于字段、证据引文或必要说明时保留，不改模板语法。 |
| 相邻句反复套同一骨架，或连续用「首先 / 其次 / 最后」开段却没有先后关系 | 在原段内按实际关系连接句子，只调整读起来机械的部分。时间线、操作顺序、并列条款和必要的因果连接词保留。 |
| 形容词或名词化短语遮住了动作，如「完成了对启动项的检查」 | 写清主语和动作，如「检查了启动项」。评价风险时用 findings 中已有的行为和影响；不补数值，不用拟人比喻代替机制。 |
| 过长前置定语或名词串让读者找不到主体、动作 | 把修饰内容放回分句；「对于 X 来说」「在 X 方面」只在不承担范围限定时删除。涉及主机、时间窗或适用条件的限定保留。 |
| 顿号清单挤在一句里，读不清各对象与行为的关系 | 按行为分成分句，完整保留影响判断的对象。资产、日志源、配置项等必须逐项列明时照列，不概括成「相关资源」。 |

- 正文不用破折号制造揭晓或强调普通判断；按句意使用逗号、句号。模板占位、原始引文和代码保持原样。
- 非术语英文口语换成通行中文，如 hands-on → 手动操作；专业术语保留原文或首次出现时括注，不自造译名。
- 判断和依据给完就收，不拖「按证据驱动原则……」等工作过程尾巴；图注只标明对象，推理留正文。
- 同句中的两层限定若只是同义复述，合并为一层；含义不同则分别保留。
- 否定限定句当固定收尾：「这只说明 X，不能说明 Y」「只能证明 X，不等于 Y」不应逐段重复套用。每个独立未知边界都要保留，不设全篇次数上限；重复的同一限定合并，优先正面写能确认的范围和缺什么记录才能推进（「上述检查覆盖近一周记录，更早的活动没有日志可查」「要判断 X 需要 Y 记录」），范围与边界的落点遵循模板及跨章节规则

## 非通行措辞

用词以国内安全工程师与客户交流的通行说法为准。读者需要理解的专业术语首次出现时简短解释，不为通俗而改掉准确含义。典型四类：

- 英文行话直译的生造词：「扇出」「机群」按 findings 中的实际行为和主机对象说明，不顺手补协议或系统类型。没有通行中文译法的术语保留英文原词，不自造译名。
- 文言 / 公文字眼：「灭失」「3 年余」「且设永不过期」→「已丢失」「三年多」「并设置为永不过期」。「已丢失」不能自行扩写成「已被覆盖」或「被攻击者删除」。
- 整句压成的名词串：「该来源在现存入站认证记录中仅一次出现」→「检索现存入站认证记录，该来源只出现过一次」。主体或修饰关系难以辨认时拆句，保留原有检索范围，不生造复合名词。
- 比喻替代平实陈述：「精确套住」→「恰好覆盖」。事实用平实动词说明，需要数字时从 findings 取值，不靠修辞加重语气。

## 成稿复核

先对照 findings 检查改写前后的对象、数字、时间关系、否定范围、判断强度与行动状态，再通读段落。每处改动都应解决具体表达问题，未引入新事实或删掉独立边界。事实或模板要求与文风冲突时，保留事实和模板要求并向编排者说明，不在客户报告中附修改记录。

改写方法参考 [lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone/blob/main/SKILL.md) 的局部修改与信息保真思路，按应急响应报告体裁取舍；不采用按标点数量或词表机械清理的方式。链接仅用于来源追溯，writer 无需联网读取。
