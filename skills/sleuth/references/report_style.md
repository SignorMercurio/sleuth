# 报告写作风格指南

步骤 8 写报告前读取本文件。目标：报告读起来像一名资深应急响应工程师写的，而不是模型生成的。下面的规则与 `assets/style/` 中的手写报告片段共同约束文风。

## 风格语料的使用

- 写作前只读 `assets/style/curated-ir-excerpts.md`（存在时）找语感；不存在才从目录中最多挑 1 篇其他材料，不为模仿文风加载额外长文。
- 样本只影响内容取舍、段落节奏和常用表达；事实、结论等级、篇幅、模板结构和本项目约束始终以 findings、模板及对应规则为准。样本里的案例、命令、IP、结论一律不得进入报告，句子也不得照抄或只换主语改写（校验器会拦截连续重合的样本原句）。
- 样本有增删后，本文件的蒸馏规则需要人工重新核对一次。

## 句法与叙述

- **结论先行，推理透明**：先给承重判断，再跟最强依据。决定结论的判断要说明证据；同一依据支撑一组相邻事实时只解释一次，不逐句重复来源。
- **用完整段落叙述，列表只用于枚举**：证据链写成「检查了 X，发现 Y，因此 Z」的连续句；并列的方法、线索与待办用列表呈现，每项是完整的动作或判断，不是两三个词的短语。
- **一段一个判断，一句一层关系**：需要缩短报告时减少低价值内容，不压缩句法。一个句子同时塞入结论、多条证据、影响、处置和限定时拆成两三句；一个段落出现两个独立判断时拆段。
- **平实、克制的书面语**：不写「遗憾的是」「好在」「不难发现」等情绪性或引导读者的转折，不堆四字格，不写排比。
- **不确定性如实标注，且双向校准**：把握程度直接用「可能 / 很可能 / 推测 / 疑 / 未必」写进句子，证据用语按模板注释区分「未观察到」「无法确认」「已排除」，不将它们互换，也不当固定收尾。多条证据指向同一结论时不过度对冲成「待进一步确认」，写「综合现有证据，攻击者很可能已经……」；不写「大概率得手」「攻击已经得手」等口语化判断，直接说明攻击者很可能完成的具体行为。不用 `[推测]` 方括号标签，也不另起一段写「本结论属高置信度推测，依据是……」的置信度元说明——把判断和依据写成一句通顺的话。
- **影响结论的数字与范围写具体**：「缩小至 3 项以内」「18:18:12 前后 ±1 秒」；不影响定性、范围或处置优先级的精确数字不必写入正文。
- **证据贴身解释**：引用日志、命令输出后立即说明它支持哪个判断，直接写「这说明……」或自然承接，不固定套用提示语。
- **中英文之间留空格**，专有名词用原文（WAF、ECS、Webshell），标点用全角中文标点。面向管理层的概述 / 结论里阿里云产品用中文名（云安全中心、云防火墙），`SAS` / `SLS` / `ActionTrail` 等缩写留给技术分析里的日志源与标识符。客户可见叙述优先写「访问日志」「进程启动记录」，不写「Access 日志」「进程遥测」；只有原始字段名、产品界面名称或日志库名称必须精确引用时才保留原文。

## 反 AI 腔清单（出现即改写）

本节与下一节列的是问题类型，例词仅示意、不穷尽；自检靠通读判断是否属于该类问题，不做按例词的机械检索——例词出现在正常语境（如「最后一次登录」「再次执行」）不算命中。

- 三段式 / 排比式结构（「不仅…而且…更…」「无论是…还是…亦或…」）
- 填充性短语：「值得注意的是」「需要指出的是」「综上所述」「总而言之」「众所周知」；「本次」只在需要与历史事件区分时用，「本次调查 / 本次排查 / 本次检查」这类默认可删
- 空洞评价词：「全面深入的分析」「高度复杂的攻击」「极大的安全隐患」——换成具体事实（复杂在哪、隐患是什么）
- 「首先 / 其次 / 再次 / 最后」式机械连接连续开段
- 每段一句话、通篇 bullet 的碎片化排版
- 正文里的「术语 :: 解释」腔与破折号滥用（模板 `:::` 指令块内的字段语法除外）
- 夹带非术语英文口语（hands-on、lateral movement、随手中英混写的 payload）——技术术语用通行中文或首次出现时括注，口语化英文直接换成中文（hands-on → 手动操作）
- 句尾拖「按 X 原则做 Y」的过程尾巴（「按推测记录并交叉其他证据」「按证据驱动原则不点亮该技术，仅在证据缺口里说明」）——判断和依据给完就收，与前面的置信度元说明同理，都是工作底稿口吻
- 图注复述正文（把相邻正文的时间、要素、限定语抄进图注）——图注一句话只标注图的对象，推理留正文
- 同句叠双层免责（「只表示 X，不能排除 Y」，而 Y 只是 X 的换个说法）——限定留一层就够
- 否定限定句当固定收尾：「这只说明 X，不能说明 Y」「只能证明 X，不等于 Y」不应逐段重复套用。每个独立未知边界都要保留，不设全篇次数上限；重复的同一限定合并，优先正面写能确认的范围和缺什么记录才能推进（「上述检查覆盖近一周记录，更早的活动没有日志可查」「要判断 X 需要 Y 记录」），范围与边界的落点遵循模板及跨章节规则

## 非通行措辞清单（出现即改写）

用词以国内安全工程师与客户口头交流的通行说法为准。自检：句子念出来，客户会停下来想「这个词什么意思」的，一律改写。典型四类：

- 英文行话直译的生造词：「扇出」「机群」「排查阴性」→「向多台主机发起 RDP 连接」「各 Windows 主机」「未发现后门」。没有通行中文译法的术语保留英文原词，不自造译名。
- 文言 / 公文字眼：「灭失」「3 年余」「且设永不过期」「史上仅此一次」→「已被覆盖丢失」「三年多」「并设置为永不过期」「此前从未出现过」。
- 整句压成的名词串：「入站鉴权全量基线中该来源史上仅此一次」「勒索工具包源」→ 拆回带动词的句子：「检索全部入站认证记录，该来源只出现过这一次」「存放勒索工具包的压缩包」。定语叠到两层就拆句，不生造复合名词。
- 比喻替代平实陈述：「精确套住」「压倒性主力」→「恰好覆盖」「绝大多数（336 次）来自堡垒机」。事实用平实动词加具体数字说，不靠修辞加重语气。
