# 能力探测（调查开始前）

SKILL.md 步骤 1 之前加载本文件。目的：先弄清本次调查**实际拿得到哪些证据源**，再据此约束结论的置信度上限，避免用缺失的能力去支撑确定性措辞。

探测本身必须零副作用：只列客户端、只看 skill 是否可调用，不为探测在受害主机上跑命令。

## 探测步骤

1. **SIREN**：调用 list client 工具（`mcp__siren__ls` 或运行环境暴露的等价物），确认工具可达且目标 Client 在线。工具名不存在、调用报错或客户端列表为空都算缺失。
2. **云侧 skill**：确认 `$sas`、`sls`、`opencli-aliyun-ir` 是否已安装可调用（看运行环境的 skill 清单，不要靠猜；不确定时在真正需要那一层证据时试调一次，失败即记为缺失）。
3. **辅助能力**：确认运行环境是否提供子 agent 机制与联网检索工具（映射与降级见 `references/runtime_compat.md`）。
4. **记录**：把缺失项、判定依据和受影响的调查方向写入 findings 的**调查范围 / 限制**部分——`references/findings_spec.md` 的「云端证据覆盖」与「证据缺口」两节；报告里按覆盖说明处理，不写成「未发生」。
5. **告知**：能力缺口影响用户预期时（如无云侧日志、无法归因真实攻击者 IP），在交付结论里一并说明。

## 缺口 → 置信度影响对照

| 缺失能力 | 证据覆盖面影响 | 相关结论的措辞上限 |
|---|---|---|
| SIREN list/run 不可达 | 无主机侧证据，调查无法开展 | 终止并告知用户，不改用本地 shell/SSH 代替 |
| `$sas` 不可用 | 无告警详情、触发规则与资产映射 | 转模式二；依赖告警内容的定性最高「推测」，并向用户索取告警摘要 |
| `sls` 不可用 | 云侧日志（WAF、SAS 进程/网络/登录遥测、ActionTrail）无法交叉验证 | 攻击者真实 IP 归因、初始入口时间点、主机日志被清时段的结论最高「推测」；「未检出」不得写成「未发生」 |
| `opencli-aliyun-ir` 不可用 | 云控制面与跨产品（云防火墙、OSS/RDS/ECS/VPC/ACK、内部控制台）为盲区 | 云资源影响范围、AK 滥用面、横向面写「无法确认」 |
| 子 agent 不可用 | 无独立核验、无写作上下文隔离、大输出需内联收窄 | 按 `references/runtime_compat.md` 内联降级；承重断言仍须逐条自检，不得因此跳过步骤 7 验证门 |
| 联网检索不可用 | CVE、Exploit、威胁情报无外部佐证 | 漏洞编号与情报归因写「推测 / 未做外部验证」 |

单一证据源支撑的结论按 `references/verification_checklist.md` 的孤证规则降级；本表只约束**能力缺失**带来的上限，两者取更严的一个。
