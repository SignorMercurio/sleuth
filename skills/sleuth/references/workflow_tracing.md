# 步骤 3–6：深度溯源、漏洞、攻击链与遗留风险

SKILL.md 进入步骤 3 时加载本文件。安全护栏以 SKILL.md 为准，本文只写操作细则。

## 调查闭环与停止条件

按步骤 2 的排查清单推进。每轮取优先级最高的可执行项，互不依赖的项同批并行：`问题/断言 → 查询身份与范围 → 新证据或缺口 → 确认/反驳/降级 → 下一步`，按 `references/findings_spec.md` 写回 findings，再选下一项。先补能改变结论的最短证据；某个分支出现重复查询、无新增信息或只会增加原始输出时，只停止该分支，把该项记为「缺口」，然后继续其他项。新证据引出的问题（新主机、新身份、新 IoC、更早或更晚的时间窗）追加为新项。

单项受阻（等客户数据、授权、主机上线或控制台登录）时，把该项标「受阻」，向用户提一次具体请求（运行时支持异步提问时不等回复），然后继续其他可执行项。不得因一项受阻停止整个调查，也不把补齐受阻项写成其他项的前提。

清单还有可执行项时不结束回合，不以「我会继续……」「下一步将……」收尾，而是直接执行。只有以下情况才收尾：

1. 每项都已确认、反驳、记为缺口或标「不适用」，且已记录步骤 6 各维度覆盖结果：进入步骤 7。
2. 剩余项全部受阻于用户、客户或授权：进入步骤 7 交付阶段结论，受阻项按缺口披露并列出所需事项；用户补齐后回到本节继续。
3. 下一步需要处置授权或超出只读护栏：说明所需授权与影响后结束回合。

用户中途提问且排查目标未变时，答完回到清单继续。不得为了凑满攻击链、CVE 或 ATT&CK 技术继续扩张调查。

## 步骤 3.1 按需加载调查指南与实战技巧

**读取 `references/playbooks.md`** 中与告警或异常对应的小节，命令仅供参考，按实际参数调整。大输出按 `references/runtime_compat.md`「重输出隔离」处理。

## 步骤 3.2 阿里云云侧交叉验证

主机证据不足或需交叉验证时，按 SKILL.md「云侧分层」和 `references/cloud_log_queries.md` 选择证据源；`$sas` 告警查询按步骤 1.2。委派时只传目标 UID、已确认的站点/地域、资产标识、时间窗、待验证的清单项和已知 IoC，不传整段对话；回传按 `references/findings_spec.md` 的证据记录格式，原始大日志先在委派侧收窄。查询语法、参数与适配器由对应 skill 管理；不可用时按 `references/runtime_compat.md` 降级，不改用本地 shell、SSH、浏览器或任意云 CLI。控制台截图等步骤 7 验证门过完再按 `references/workflow_delivery.md` 委派。

## 步骤 4 入口与漏洞定位（按证据）

先判断证据支持的初始入口。只有证据指向漏洞利用时，才识别漏洞类型、受影响组件与版本、Payload，并用运行环境提供的联网检索工具核对 CVE、Exploit 与修复方案；不可联网时说明未做外部验证。入口是凭证滥用、合法工具滥用、配置暴露或社会工程时，记录该入口并写「未发现需要绑定的漏洞」；入口证据不足写「无法确认」。不得为了字段完整或告警名称强行匹配 CVE。

## 步骤 5 攻击链重建

按 ATT&CK 战术阶段映射并构建时间线。编号基准为 MITRE ATT&CK v18。优先用具体子技术编号；每条映射有证据支撑，同一行为可跨多个战术（如定时任务属执行/持久化/权限提升）；未涉及的战术在文字映射里省略（报告矩阵版式固定，见 `references/report_writing_rules.md`）。

## 步骤 6 遗留风险排查

六维均需记录覆盖：恶意文件 / 定时任务 / 启动项与服务 / 账户与授权 / 网络连接 / 系统完整性。先复用步骤 2–5 仍有效的结果，再补缺；每维写检查对象、时间范围与结论，未查/失败/截断不能填成「未观察到」。Linux 轻量检查包括相关临时目录、全用户 crontab、systemd/rc.local/init.d、passwd/authorized_keys/sudoers.d、当前连接，以及 `ld.so.preload`/profile 中的 `LD_PRELOAD`，合并调用同步骤 2「调用效率」；Windows 与容器按等价维度，缺工具或权限则记录限制。云侧事件的六维改为：凭据（AK / STS / 控制台密码）/ RAM 用户与授权 / 角色与信任策略 / 新建或改动的云资源 / 网络与访问控制（安全组、WAF、白名单）/ 审计与日志完整性（Trail、LogStore 删改）；按 `references/tech_cloud.md`「AK 泄露利用方式总结」对应 API 核查，无可疑信号的维度只做最小核查（如 AK 最近使用）并写明范围。

可疑项才加载 `references/recon_residual.md`。包完整性先核验证据涉及的二进制及所属包；发现工具替换、包级异常或必须排除更广篡改时再做 `rpm -Va`/`dpkg -V`。全盘搜索、全包校验与大日志扫描须先写出待证问题和范围，逐级扩大；超时按运行机制降级，不将未完成扫描视为阴性。
